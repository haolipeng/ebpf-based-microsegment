# Task: Integrate TCP State Machine with XDP Program

## Description
Integrate the TCP state machine into the XDP (eXpress Data Path) eBPF program. Create an XDP-specific state update function that handles the ingress-only limitation and update both hot path and new session initialization.

## Acceptance Criteria
- [x] `update_tcp_state_xdp()` function added to XDP program
- [x] Hot path updated to track TCP state
- [x] New sessions initialized with correct TCP state
- [x] Ingress-only limitation handled correctly
- [x] State-based closing detection implemented
- [x] No performance regression

## Technical Details

**Changes to xdp_microsegment.bpf.c**:

1. **Include header**:
```c
#include "headers/tcp_state_machine.h"
```

2. **New function**:
```c
static __always_inline __u8 update_tcp_state_xdp(
    struct xdp_md *ctx,
    struct flow_key *key,
    __u8 current_state)
```

3. **Hot path update**:
```c
if (key.protocol == IPPROTO_TCP) {
    __u8 old_tcp_state = session->tcp_state;
    session->tcp_state = update_tcp_state_xdp(ctx, &key, old_tcp_state);

    if (is_tcp_state_closing(session->tcp_state) && ...)
        session->state = SESSION_STATE_CLOSING;
}
```

4. **New session initialization**:
```c
__u8 initial_tcp_state = TCP_STATE_CLOSED;
if (key.protocol == IPPROTO_TCP) {
    initial_tcp_state = update_tcp_state_xdp(ctx, &key, TCP_STATE_CLOSED);
}
```

**XDP-Specific Considerations**:
- Only sees ingress traffic (incoming packets)
- Uses `tcp_state_transition_inbound()` exclusively
- Cannot track outbound client-initiated connections fully
