# Task: TC/XDP 程序进程策略匹配

## Description

扩展现有的 TC 和 XDP 微隔离程序，支持基于进程信息（进程名称、进程路径）的策略匹配。在数据包处理路径中获取当前进程信息，查询 `process_info_map` 获取缓存的容器 ID，并实现多级策略优先级（进程策略 > 网络策略）。

**核心目标**:
- 在 TC/XDP 程序中获取当前进程 PID 和 comm
- 查询 Task 001 创建的 `process_info_map` 获取完整进程信息
- 实现进程策略匹配逻辑（process_name + process_path 组合匹配）
- 实现策略优先级（包含进程字段的策略优先于纯网络策略）
- 在 flow_event 中填充进程字段（供用户态展示）

## Acceptance Criteria

- [ ] TC/XDP 程序能成功获取当前进程 PID 和 comm
- [ ] 成功查询 `process_info_map` 并获取容器 ID
- [ ] 创建 `process_policy_map` 用于存储进程策略（用户态下发）

- [ ] 实现策略优先级算法（多级优先级）
- [ ] flow_event 包含完整进程信息（process_name, pid, container_id）
- [ ] 测试验证：进程策略优先于网络策略执行

**扩展策略数据结构**:
```c
// policy.h

// Policy entry (扩展支持进程字段)
struct policy_entry {
    // Existing network fields
    __u32 src_ip;
    __u32 dest_ip;
    __u16 src_port;
    __u16 dest_port;
    __u8 protocol;

    // New process fields
    char process_name[16];      // Process command name (optional)
    char process_path[128];     // Process executable path (optional)

    // Policy metadata
    __u8 action;                // ALLOW / DENY
    __u8 priority;              // Auto-calculated: process policy > network policy
};

// Process policy map (存储含进程字段的策略)
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 5000);
    __type(key, struct policy_key);
    __type(value, struct policy_entry);
} process_policy_map SEC(".maps");
```

**TC 程序扩展**:
```c
// tc_microsegment.bpf.c

SEC("tc/egress")
int tc_microsegment_egress(struct __sk_buff *skb)
{
    // 1. Parse network headers (existing logic)
    struct flow_tuple flow = {};
    if (parse_packet(skb, &flow) < 0)
        return TC_ACT_OK;

    // 2. Get current process information
    struct process_info proc = {};
    __u64 pid_tgid = bpf_get_current_pid_tgid();
    proc.pid = pid_tgid >> 32;
    bpf_get_current_comm(&proc.comm, sizeof(proc.comm));

    // 3. Lookup process cache (from Task 001)
    struct process_cache_entry *cached = bpf_map_lookup_elem(&process_info_map, &proc.pid);
    if (cached) {
        __builtin_memcpy(proc.container_id, cached->container_id, sizeof(proc.container_id));
        proc.exec_time = cached->exec_time;
    }

    // 4. Policy matching with priority
    __u8 action = TC_ACT_SHOT;  // Default: DENY

    // 4.1 Try process policy first (higher priority)
    action = match_process_policy(&flow, &proc);
    if (action != POLICY_NOT_FOUND)
        goto enforce_policy;

    // 4.2 Fallback to network policy
    action = match_network_policy(&flow);

enforce_policy:
    // 5. Send flow event to userspace
    struct flow_event event = {};
    fill_flow_event(&event, &flow, &proc, action);
    bpf_ringbuf_output(&flow_events, &event, sizeof(event), 0);

    // 6. Enforce policy
    return (action == ACTION_ALLOW) ? TC_ACT_OK : TC_ACT_SHOT;
}

// Helper: Match process policy
static __always_inline __u8 match_process_policy(struct flow_tuple *flow, struct process_info *proc)
{
    struct policy_key key = {};

    // Build policy key (network + process)
    key.src_ip = flow->src_ip;
    key.dest_ip = flow->dest_ip;
    key.dest_port = flow->dest_port;
    key.protocol = flow->protocol;

    // NOTE: eBPF cannot use process_name as map key directly (variable length)
    // Solution: User-space pre-computes policy keys and stores in map

    struct policy_entry *policy = bpf_map_lookup_elem(&process_policy_map, &key);
    if (!policy)
        return POLICY_NOT_FOUND;

    // Verify process fields match (AND logic)
    if (policy->process_name[0] != '\0') {
        if (__builtin_memcmp(policy->process_name, proc->comm, sizeof(proc->comm)) != 0)
            return POLICY_NOT_FOUND;
    }

    // Note: process_path will be verified in userspace (Task 3)
    // eBPF only matches process_name due to path length limitations

    return policy->action;
}

// Helper: Fill flow event with process info
static __always_inline void fill_flow_event(struct flow_event *event,
                                            struct flow_tuple *flow,
                                            struct process_info *proc,
                                            __u8 action)
{
    // Fill network fields (existing logic)
    event->src_ip = flow->src_ip;
    event->dest_ip = flow->dest_ip;
    // ...

    // Fill process fields (new)
    __builtin_memcpy(event->process_name, proc->comm, sizeof(event->process_name));
    event->pid = proc->pid;
    __builtin_memcpy(event->container_id, proc->container_id, sizeof(event->container_id));
    event->process_exec_time = proc->exec_time;

    event->action = action;
}
```

**策略优先级算法**:
```
Priority levels (high → low):
1. Process + Network policy (process_name + dest_port)
2. Network-only policy (dest_port only)
3. Default policy (DENY)

Matching strategy:
- Step 1: Query process_policy_map with (network + process)
- Step 2: If not found, query network_policy_map with (network only)
- Step 3: If still not found, apply default DENY
```

### 代码模式

- **Map 查询优化**: 先查询高优先级 map，避免不必要的查询
- **内存安全**: 使用 `__builtin_memcmp` 比较字符串（eBPF verifier 友好）
- **错误处理**: Map 查询失败时回退到下一级策略
- **性能考虑**: 单次查询延迟 < 2μs（LRU map 性能）
