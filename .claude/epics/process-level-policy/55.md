# Task: 集成测试、性能测试和文档

## Description
Comprehensive end-to-end testing and documentation for the process-level policy enforcement feature. This final integration task validates the entire system through functional tests, performance benchmarks, and security tests, ensuring all components work together correctly under realistic conditions.

The task also produces user-facing documentation (manual, API reference) and internal documentation (architecture, troubleshooting) to support deployment and maintenance.

## Acceptance Criteria
**End-to-End Functional Tests:**
- [ ] Process monitoring test: Verify eBPF programs capture process metadata (name, path, PID, container ID)
- [ ] Policy matching test: Validate process-based policy rules (allow/deny by process name/path)
- [ ] Container ID extraction test: Confirm accurate container ID from cgroup paths
- [ ] Dashboard integration test: Verify flow list displays process columns correctly
- [ ] Security alert test: Trigger policy violations and verify alerts appear

**Simplified Performance Tests (3 basic scenarios from PRD):**
- [ ] High connection rate: 10,000 concurrent connections with process tracking
- [ ] Container density: 100 containers with mixed process policies
- [ ] Policy rule scale: 1,000 process-based rules loaded

**Security Tests:**
- [ ] Path spoofing test: Attempt to forge exe_path and verify detection
- [ ] Process deception test: Validate PID/TGID consistency checks
- [ ] Container escape test: Ensure host processes don't match container policies

**Documentation:**
- [ ] User Manual: Installation, policy configuration, dashboard usage, troubleshooting
- [ ] API Documentation: Policy CRUD endpoints, alert endpoints, flow query API
- [ ] Architecture Documentation: eBPF program design, data flow, component interaction
- [ ] Security Guide: Threat model, security considerations, best practices

## Technical Details
Create a comprehensive test suite and documentation set:

**Key files to create:**

**Code patterns to follow:**
- Use Go testing framework for backend/eBPF tests
- Use Playwright or Cypress for dashboard UI tests
- Implement test fixtures for realistic container environments
- Use benchmark utilities (Go benchmarks, Linux perf) for performance tests
- Structure tests with setup/teardown for reproducibility
- Document all test scenarios with expected outcomes

**Performance test baselines (from PRD):**
- Connection rate: 10,000 conn/s with <5% CPU overhead
- Container density: 100 containers with <10ms policy lookup latency
- Policy scale: 1,000 rules with <1ms matching time

**Security test scenarios:**
- Path spoofing: Use LD_PRELOAD or symlinks to forge paths
- Process deception: Test PID reuse scenarios
- Container escape: Validate cgroup-based isolation enforcement
