# Task 15: Phase 2 生产环境部署

## Overview

将 LPM Trie 优化部署到生产环境,配置完整的监控体系,执行分阶段灰度发布,确保零停机时间和快速回滚能力。

## Objective

安全、有序地将 LPM Trie 优化部署到生产环境,通过灰度发布和实时监控验证性能提升,并建立完整的运维文档和回滚机制。

## Description

执行 Phase 2 优化的完整生产环境部署,包括:

1. **灰度发布策略**:
   - 制定分阶段发布计划(10% → 50% → 100%)
   - 设计策略迁移时间表
   - 定义回滚触发条件

2. **Feature Flag 配置**:
   - 实现运行时开关控制 LPM 启用/禁用
   - 支持按集群、节点、用户维度灰度
   - 快速回滚无需重启服务

3. **监控体系完善**:
   - Prometheus metrics(策略查询延迟、丢包率等)
   - Grafana 大盘(实时性能监控)
   - 告警规则(异常检测、阈值告警)

4. **执行策略迁移**:
   - Phase 1: 10% 集群启用 LPM Trie(验证稳定性)
   - Phase 2: 50% 集群启用(确认性能提升)
   - Phase 3: 100% 集群启用(完全迁移)
   - 每阶段监控 24 小时以上

5. **性能监控验证**:
   - 实时对比 Array Map vs LPM Trie 性能
   - 验证关键指标达成(P99 <5μs)
   - 检测异常并触发告警

6. **运维文档**:
   - Runbook(操作手册): 灰度发布、回滚步骤
   - 故障诊断指南: 常见问题和解决方案
   - 监控告警说明: 指标含义和响应策略

7. **回滚演练**:
   - 测试完整的回滚流程
   - 验证回滚时间和数据一致性
   - 记录演练结果

## Technical Details

### Feature Flag 架构

```go
// Feature flag 配置结构
type FeatureFlags struct {
    EnableLPM bool
    LPMConfig LPMConfig
}

type LPMConfig struct {
    Enabled          bool
    Rollout          RolloutStrategy  // 灰度策略
    ClusterSelector  []string         // 指定集群启用
    NodeSelector     map[string]string // 指定节点启用
    PercentageRollout uint32           // 启用百分比(0-100)
}

type RolloutStrategy struct {
    Type       string        // "percentage" | "cluster" | "node"
    Percentage uint32        // 百分比灰度
    Clusters   []string      // 按集群灰度
    Nodes      map[string]bool // 按节点灰度
}

// 在 WildcardPolicyManager 中使用
func (m *WildcardPolicyManager) useLPMTrie() bool {
    flags := m.loadFeatureFlags()
    return flags.EnableLPM && m.matchesRolloutStrategy(flags.LPMConfig)
}
```

### 灰度发布计划

#### 阶段 1: 金丝雀部署 (10% 集群)

```
时间: T+0 ~ T+24h
目标: 验证 LPM Trie 基础功能和稳定性

步骤:
1. 选择 1-2 个低流量集群(开发、灰度集群)
2. 启用 LPM Trie Feature Flag
3. 运行 24 小时,监控关键指标:
   - CPU 使用率不增加
   - 内存占用合理
   - 错误率 <0.1%
   - 无丢包或丢包率 <0.01%
4. 验证通过 → 进入阶段 2

回滚条件:
- 错误率 >0.5%
- 丢包率 >0.05%
- 服务不可用
```

#### 阶段 2: 小规模扩展 (50% 集群)

```
时间: T+24h ~ T+48h
目标: 确认性能提升,验证可伸缩性

步骤:
1. 扩展到 50% 集群(多个大集群)
2. 逐步启用 LPM Trie(分批灰度)
3. 运行 24 小时,监控:
   - 平均延迟降低 >30%
   - P99 延迟 <5μs
   - 吞吐量 ≥当前值
   - 丢包率 <0.01%
4. 验证通过 → 进入阶段 3

回滚条件:
- 性能未改善(延迟增加或不变)
- 丢包率 >0.01%
- 内存泄漏迹象
```

#### 阶段 3: 完全部署 (100% 集群)

```
时间: T+48h+
目标: 完全迁移到 LPM Trie

步骤:
1. 启用所有集群的 LPM Trie
2. 保留 Array Map 作为后备方案
3. 持续监控(后续 2 周)
4. 建立长期 SLA 指标

维护:
- Array Map 保留期: 2 周
- 验证无问题后可安全删除 Array Map
```

### Prometheus 告警规则

```yaml
# prometheus-rules.yaml

groups:
  - name: lpm_performance
    rules:
      # P99 延迟告警
      - alert: LPMHighP99Latency
        expr: histogram_quantile(0.99, policy_lookup_duration_us{type="lpm"}) > 10
        for: 5m
        annotations:
          summary: "LPM P99 延迟过高"
          description: "P99 延迟 > 10μs, 当前值 {{ $value }}μs"

      # 丢包率告警
      - alert: HighPacketDropRate
        expr: packet_drop_rate > 0.01
        for: 2m
        annotations:
          summary: "丢包率过高"
          description: "丢包率 > 0.01%, 当前值 {{ $value }}"

      # 错误率告警
      - alert: HighPolicyLookupErrorRate
        expr: rate(policy_lookup_errors_total[5m]) > 0.18
        for: 5m
        annotations:
          summary: "策略查询错误率高"
          description: "错误率 > 0.1%, 当前值 {{ $value }}"

      # LPM Trie 条目溢出
      - alert: LPMTrieEntriesAlmostFull
        expr: lpm_trie_entries / lpm_trie_max_entries > 0.9
        for: 10m
        annotations:
          summary: "LPM Trie 条目即将满"
          description: "利用率 > 90%, 需要扩容"
```

4. 继续监控 24 小时

指标检查清单:
- [ ] P99 延迟 <5μs
- [ ] 相对 Array 性能提升 >30%
- [ ] 丢包率 <0.01%
- [ ] 无内存泄漏

### 步骤 3: 100% 集群(T+48h)

1. 执行紧急回滚: Feature Flag EnableLPM = false
