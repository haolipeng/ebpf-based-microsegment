# eBPF 循环常量化与早停优化

## 描述

将硬编码的 100 替换为 MAX_WILDCARD_LOOP 常量(设为 50),实现早停逻辑(遇到空槽位立即 break)

## 受影响的文件

- src/bpf/headers/policy_match.h

## 验收标准

- [ ] 定义 MAX_WILDCARD_LOOP 常量为 50
- [ ] 修改循环逻辑使用该常量
- [ ] 实现早停优化(空槽位时 break)
- [ ] eBPF verifier 验证通过
- [ ] 单元测试覆盖率 >80%

S (4-8 小时)

## 技术细节

### 当前状态
目前在 policy_match.h 中的通配符匹配循环使用了硬编码的迭代次数 100，这会导致不必要的计算，尤其在策略数量较少时。

### 实现方案

1. **定义常量**
   - 在 policy_match.h 中定义 `#define MAX_WILDCARD_LOOP 50`
   - 常量值基于性能测试结果

2. **修改循环逻辑**
   - 将循环条件从 `i < 100` 改为 `i < MAX_WILDCARD_LOOP`
   - 确保所有通配符匹配循环都使用此常量

3. **实现早停优化**
   - 检测到空槽位(NULL 或标记为空的条目)时立即 break
   - 避免继续扫描已确认为空的区域

4. **eBPF 验证**
   - 通过 eBPF verifier 的循环边界检查
   - 确保指针操作安全性

### 测试计划

1. 单元测试
   - 测试不同长度的策略列表
   - 验证早停逻辑正确性
   - 覆盖边界情况

2. 性能测试
   - 对比优化前后的延迟
   - 测试实际策略加载场景
