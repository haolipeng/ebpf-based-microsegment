## 技术细节

### 当前状态
Server 端策略存储当前采用简单的追加模式，删除后留下空槽位但不重用，导致 eBPF 层需要扫描大量空槽位。

### 实现方案

1. **数据结构设计**
   - 维护 `first_free_index` 指针
   - 跟踪已使用槽位和空槽位
   - 可选：维护空槽位的链表，用于快速查找下一个可用位置

2. **策略添加逻辑**
   - 检查 `first_free_index` 是否有效
   - 如果有，使用该槽位存储新策略
   - 更新 `first_free_index` 为下一个空槽位
   - 如果无空槽位，追加到列表末尾

3. **策略删除逻辑**
   - 标记对应槽位为空（可使用特殊值或标志位）
   - 如果删除的槽位索引 < 当前 `first_free_index`，更新指针
   - 同步更新 eBPF map

4. **eBPF map 同步**
   - 确保 Server 端的槽位管理与 eBPF map 的数据一致
   - 实现高效的批量更新机制

### 测试计划

1. 单元测试
   - 添加-删除-添加循环测试
   - 验证 first_free_index 的正确性
   - 边界情况：全满、全空、部分碎片化

2. 集成测试
   - Server 端存储与 eBPF map 同步验证
   - 测试高并发的添加删除操作

3. 性能测试
   - 对比紧凑存储前后的存储效率
   - 验证 eBPF 层的查找延迟改进

```go
// 伪代码示例
type PolicyStorage struct {
    policies       []*Policy
    firstFreeIndex int
    freeList       []int  // 可选：维护空槽位列表
}

func (ps *PolicyStorage) AddPolicy(p *Policy) error {
    if ps.firstFreeIndex < len(ps.policies) {
        ps.policies[ps.firstFreeIndex] = p
        ps.updateFirstFreeIndex()
    } else {
        ps.policies = append(ps.policies, p)
    }
    return ps.syncWithEBPF()
}

func (ps *PolicyStorage) DeletePolicy(idx int) error {
    ps.policies[idx] = nil
    if idx < ps.firstFreeIndex {
        ps.firstFreeIndex = idx
    }
    return ps.syncWithEBPF()
}
```
