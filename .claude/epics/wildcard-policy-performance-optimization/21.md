## 技术细节

### 测试目标

1. 建立不同策略数量下的性能基线
2. 验证 Task 18 和 Task 19 的性能提升
3. 作为未来优化的参考点

### 基准测试设计

1. **测试场景**
   - 10 条策略的查询
   - 50 条策略的查询
   - 100 条策略的查询
   - 可选：200/500 条策略

2. **测试指标**
   - P50、P95、P99 延迟（单位：微秒）
   - 平均延迟
   - 最大延迟
   - 吞吐量（每秒查询次数）

3. **测试方法**
   - 热预热：运行 1000+ 次查询预热 CPU cache
   - 测试运行：执行 10000+ 次查询收集数据
   - 重复运行：至少 3 次以计算平均值

### 实现计划

1. **eBPF 程序编写**
   - 创建专用的基准测试 eBPF 程序
   - 使用 `bpf_ktime_get_ns()` 记录时间戳
   - 收集查询延迟数据到 BPF map

2. **用户态测试工具**
   - 加载 eBPF 程序
   - 生成不同数量的测试策略
   - 读取性能数据并进行统计分析
   - 生成报告

3. **报告生成**
   - 输出 Markdown 格式报告
   - 包含表格显示不同场景的性能指标
   - 可视化图表（可选）

### 测试代码框架

```c
// benchmark_policy_lookup.c 伪代码
#include <uapi/linux/bpf.h>

// Store latency samples
BPF_ARRAY(latency_samples, u64, 10000);
BPF_ARRAY(sample_count, u64, 1);

// Benchmark entry point
int trace_policy_lookup(struct pt_regs *ctx) {
    u64 start_time = bpf_ktime_get_ns();

    // Call actual policy lookup function
    // policy_match_lookup(...)

    u64 end_time = bpf_ktime_get_ns();
    u64 latency = end_time - start_time;

    // Store sample
    u32 idx = 0;
    u64 *count = sample_count.lookup(&idx);
    if (count && *count < 10000) {
        latency_samples.update(count, &latency);
        u64 new_count = *count + 1;
        sample_count.update(&idx, &new_count);
    }

    return 0;
}
```
