# Task 9: 策略自动迁移工具

## Overview

实现自动迁移工具,将现有 Array Map 策略无缝迁移到 LPM Trie,确保零停机时间和完整的回滚能力。

## Objective

开发完整的策略迁移方案,支持批量迁移、双写验证、详细日志、回滚机制和命令行工具,实现生产环境安全部署。

## Description

实现一个健壮的迁移工具,将当前基于 Array Map 的策略迁移到新的 LPM Trie 架构。该工具应该:

1. **自动迁移**: 逐条扫描并转换所有现有策略
2. **双写验证**: 同时写入 Array Map 和 LPM Trie,对比结果确保一致性
3. **批量操作**: 支持分批迁移,避免一次性加载过多数据
4. **回滚机制**: 实现快速回滚,恢复到迁移前状态
5. **详细日志**: 记录每条策略的迁移状态、耗时、验证结果
6. **CLI 工具**: 提供 migrate 命令,支持多种选项
7. **进度追踪**: 显示迁移进度、成功/失败统计

## Technical Details

### 迁移工具架构

```go
// Migrator 对象管理迁移过程
type Migrator struct {
    manager *WildcardPolicyManager
    logger  *log.Logger
    config  MigrationConfig
}

type MigrationConfig struct {
    BatchSize    int           // 每批迁移策略数
    MaxWorkers   int           // 并发数
    Verify       bool          // 是否启用双写验证
    DryRun       bool          // 模拟迁移
    VerifyAll    bool          // 全量对比验证
}

type MigrationResult struct {
    TotalPolicies   int
    SuccessCount    int
    FailureCount    int
    VerifyPass      bool
    Duration        time.Duration
    FailedPolicies  []*FailedPolicy
}
```

### 迁移流程

```
1. 准备阶段
   - 加锁(防止并发修改)
   - 读取所有 Array 中的策略
   - 创建快照用于回滚

2. 迁移阶段
   - 按 batch_size 分批
   - 并发写入 LPM Trie
   - 记录每条策略的迁移状态

3. 验证阶段(可选)
   - 随机抽样验证(10% 策略)
   - 或全量验证(verify_all 时)
   - 对比 Array 和 LPM 查询结果

4. 提交阶段
   - 验证成功: 清理 Array Map,切换到 LPM
   - 验证失败: 自动触发回滚

5. 回滚阶段
   - 删除 LPM Trie 中的所有策略
   - 恢复 Array 中的快照
   - 记录回滚日志
```

### 双写验证

```go
// 验证函数对比 Array 和 LPM 查询结果
type VerifyResult struct {
    RuleID         uint32
    ArrayResult    *Policy
    LPMResult      *Policy
    Match          bool  // 结果是否一致
    Error          string
}

// 验证流程
1. 构造测试 5-tuple(src_ip, dst_ip, src_port, dst_port, protocol)
2. Array 查询: policy_manager.LookupArray(5tuple)
3. LPM 查询: policy_manager.LookupLPM(5tuple)
4. 对比结果: rule_id, action, priority 必须相同
5. 记录差异
```

### 回滚机制

```go
// 快照结构用于回滚
type MigrationSnapshot struct {
    Timestamp  time.Time
    Policies   map[uint32]*Policy  // rule_id -> Policy
    ArrayIndex uint32              // first_free_index 状态
    Version    uint64
}

// 回滚流程
1. 读取快照
2. 清空 LPM Trie
3. 恢复 Array 中的所有策略
4. 恢复 first_free_index
5. 验证恢复成功
```

### CLI 命令设计

```bash
# 查看迁移状态
migrate status

# 模拟迁移(dry-run)
migrate prepare --dry-run --batch-size=100

# 执行迁移
migrate start --batch-size=100 --max-workers=4 --verify

# 验证迁移结果
migrate verify [--sample-rate=0.1|--all]

# 回滚迁移
migrate rollback

# 查看迁移日志
migrate logs [--tail=100]

# 获取迁移统计
migrate stats
```
