## 架构概览

系统采用经典的**数据平面 + 控制平面**分离架构：

```
┌─────────────────────────────────────────────────────┐
│                   控制平面 (User Space)              │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐ │
│  │ API Server  │  │   Policy    │  │    Flow     │ │
│  │   (Gin)     │  │   Manager   │  │  Collector  │ │
│  └──────┬──────┘  └──────┬──────┘  └──────┬──────┘ │
└─────────┼────────────────┼────────────────┼────────┘
          │                │                │
          │   eBPF Maps    │   Ring Buffer  │
          │                │                │
┌─────────┼────────────────┼────────────────┼────────┐
│         ▼                ▼                ▼        │
│  ┌─────────────────────────────────────────────┐  │
│  │            TC eBPF Program                  │  │
│  │  - 数据包解析                                │  │
│  │  - 会话追踪                                  │  │
│  │  - 策略匹配                                  │  │
│  │  - 策略执行                                  │  │
│  └─────────────────────────────────────────────┘  │
│                   数据平面 (Kernel Space)          │
└───────────────────────────────────────────────────┘
```

## 核心组件

### 数据平面组件

| 组件 | 类型 | 功能 |
|------|------|------|
| `session_map` | LRU_HASH | 会话状态追踪 |
| `policy_map` | HASH | 精确策略匹配 |
| `wildcard_policy_map` | ARRAY | 通配符策略匹配 |
| `stats_map` | PERCPU_ARRAY | 统计计数器 |
| `flow_events` | RINGBUF | 事件上报通道 |

### 控制平面组件

| 组件 | 语言 | 功能 |
|------|------|------|
| API Server | Go | HTTP REST API |
| Policy Manager | Go | 策略 CRUD 和同步 |
| Flow Collector | Go | 事件收集和处理 |
| DataPlane Manager | Go | eBPF 程序管理 |

## 性能指标

| 指标 | 数值 | 说明 |
|------|------|------|
| 热路径延迟 | < 1μs | 已有会话数据包 |
| 冷路径延迟 | < 20μs | 新会话数据包 |
| 会话容量 | 100K | LRU 自动淘汰 |
| 策略容量 | 10K+ | 支持精确和通配符 |
