# 规范增量：控制平面 API 生产特性

本增量为服务端控制平面 API 添加生产就绪特性。

---

## 新增需求

### 需求：完整的策略管理 API

服务端必须提供完整的策略管理 CRUD 操作。

#### 场景：通过 API 创建策略

**前提** 服务端正在运行
**当** 向 /api/v1/policies 发送 POST 请求并携带有效的策略数据
**那么** 策略必须被创建到数据库中
**并且** 策略版本必须递增
**并且** 所有已订阅的 agents 必须收到新策略
**并且** 响应必须返回 201 Created 及策略 ID

#### 场景：通过 API 更新策略

**前提** 存在 rule_id=100 的策略
**当** 向 /api/v1/policies/100 发送 PUT 请求并携带更新数据
**那么** 策略必须在数据库中更新
**并且** 策略版本必须递增
**并且** 所有已订阅的 agents 必须收到策略更新
**并且** 响应必须返回 200 OK 及更新后的策略

#### 场景：通过 API 删除策略

**前提** 存在 rule_id=100 的策略
**当** 向 /api/v1/policies/100 发送 DELETE 请求
**那么** 策略必须从数据库中移除
**并且** 策略版本必须递增
**并且** 所有已订阅的 agents 必须收到删除通知
**并且** 响应必须返回 204 No Content

### 需求：Agent 详情 API

服务端必须提供单个 agent 的详细信息。

#### 场景：获取 Agent 详情

**前提** agent_id="agent-001" 的 agent 已注册
**当** 向 /api/v1/agents/agent-001 发送 GET 请求
**那么** 响应必须返回 200 OK
**并且** 包含 agent 元数据 (hostname, version, IPs)
**并且** 包含最新指标 (CPU, memory, packets)
**并且** 包含连接状态 (online/offline)
**并且** 包含最后心跳时间戳

#### 场景：Agent 不存在

**前提** 不存在 agent_id="nonexistent" 的 agent
**当** 向 /api/v1/agents/nonexistent 发送 GET 请求
**那么** 响应必须返回 404 Not Found
**并且** 包含错误消息 "Agent not found"

### 需求：容器部署

服务端必须可以作为 Docker 容器部署。

#### 场景：Docker 镜像构建

**前提** Dockerfile 存在
**当** 执行 docker build
**那么** 镜像必须构建成功
**并且** 镜像大小必须 <500MB
**并且** 镜像必须包含健康检查
**并且** 镜像必须以非 root 用户运行

#### 场景：完整技术栈部署

**前提** docker-compose.yml 存在
**当** 执行 docker-compose up
**那么** PostgreSQL 必须启动并处于健康状态
**并且** Server 必须启动并连接到数据库
**并且** 健康端点必须返回健康状态
**并且** 所有服务必须在失败时自动重启

### 需求：可观测性

服务端必须暴露指标并提供结构化日志。

#### 场景：Prometheus 指标

**前提** 服务端正在运行
**当** 访问 /metrics 端点
**那么** 必须返回 Prometheus 格式的指标
**并且** 包含按端点和状态分类的 HTTP 请求计数器
**并且** 包含 gRPC 请求耗时
**并且** 包含数据库查询计数
**并且** 包含自定义业务指标 (agents, flows)

#### 场景：结构化日志

**前提** 服务端正在处理请求
**当** 日志启用时
**那么** 日志必须为 JSON 格式
**并且** 包含用于请求追踪的关联 ID
**并且** 包含严重级别 (debug, info, warn, error)
**并且** 包含结构化字段 (endpoint, latency, status)

#### 场景：健康检查

**前提** 服务端正在运行
**当** 访问 /health 端点
**那么** 必须返回存活状态 (server running)
**并且** 必须返回就绪状态 (database connected)
**并且** 必须检查依赖健康状态
**并且** 健康时返回 200,不健康时返回 503

### 需求：安全加固

服务端必须支持 TLS 和限流。

#### 场景：TLS 支持

**前提** 在 server.yaml 中配置了 TLS
**当** 服务端启动
**那么** HTTP 服务器必须启用 HTTPS
**并且** gRPC 服务器必须启用 gRPC TLS
**并且** 自签名证书必须可用于测试
**并且** 自定义证书必须可配置

#### 场景：限流

**前提** 限流已启用
**当** 客户端超过速率限制
**那么** 服务端必须返回 429 Too Many Requests
**并且** 包含 Retry-After 响应头
**并且** 包含 X-RateLimit 响应头 (limit, remaining, reset)
**并且** 继续为未超限的请求提供服务

### 需求：CI/CD 自动化

项目必须具有自动化构建和部署流水线。

#### 场景：持续集成

**前提** 代码被推送到仓库
**当** CI 工作流执行
**那么** 必须编译服务端
**并且** 运行所有测试及覆盖率检查
**并且** 运行 linters (golangci-lint, gosec)
**并且** 构建 Docker 镜像
**并且** 任何步骤失败时使构建失败

#### 场景：容器发布

**前提** 主分支上的 CI 构建通过
**当** 发布工作流执行
**那么** Docker 镜像必须推送到仓库
**并且** 使用语义化版本标记
**并且** 标记为 "latest"
**并且** 镜像层必须被缓存以加快构建速度

- Agent 详情 API: 返回全面信息

- 指标: Prometheus 抓取正常工作
- TLS: HTTPS 和 gRPC TLS 正常运行
- CI/CD: 自动化构建和发布
